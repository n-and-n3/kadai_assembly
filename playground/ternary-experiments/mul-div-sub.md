# 32 trit の減算・乗算・除算の実験

対象は `-1=01, 0=00, +1=10` を64 bitに32桁詰めた値。実装・照合・ベンチは [`packed32.cpp`](packed32.cpp) にある。一般の乗除算の比較対象は packed 値を符号付き整数へ復号し、CPU の `imul` / `idiv` を使い、結果を再符号化する実装である。

## 減算: packed のまま

一時的な biased BCT 表現 `-=00, 0=01, +=10` では、各桁の符号反転が `2-digit` になる。全桁をまとめると `neg_bct(y)=0xAAAAAAAAAAAAAAAA-y`。各2 bit桁が0～2なので、この減算で桁間借りは起きない。したがって現在の符号化 `x,y` に対し、

```cpp
a = to_biased_bct(x);
b = 0xAAAAAAAAAAAAAAAAULL - to_biased_bct(y);
result = to_biased_bct(add_unsigned_bct_fast(
             add_unsigned_bct_fast(a, b), 0x5555555555555556ULL));
```

で `x-y (mod 3^32)` を計算できる。第2項を元の符号化で反転してから加算関数へ渡す版より、BCT 変換・反転をまとめた版の方がこの測定では速い。全幅乱数20万組で、オーバーフロー時の循環結果を含めて照合した。導出の基礎は [Jones の BCT 表現と加減算](https://homepage.divms.uiowa.edu/~jones/ternary/libtern.shtml)。

## 乗算: 非ゼロ trit が少ない定数

`3^k` 倍は **2 bitずつ左シフト**するだけで、`-3^k` 倍はさらに全桁の符号を反転する。ワードから落ちた桁は `3^32` を法として失われるため、範囲エラーを採用するなら別途検出が必要である。`k=0` は `±1` 倍。

乗数の非ゼロ trit が2個なら、例えば `3^i-3^j` 倍を `x<<2i` と `-(x<<2j)` の直接 packed 加算で計算できる。実験関数 `trit_mul_sparse2_mod` はこの方法で `mod 3^32` の積を返す。乗数が sparse かどうかは、現在の符号化では `popcnt` で判定できる。`trit_mul_hybrid` は一般の値には変換方式を使い、2 trit 案については最高位桁の和が30以下のときだけ選ぶ。この条件なら `|x| < 3^(h+1)/2`、`|y| ≤ 3^k+3^(k-1)` から `|xy| < 2·3^(h+k) ≤ 2·3^30 < (3^32-1)/2` と分かり、範囲外にはならない。条件を満たさなくても結果が範囲内の例はあり、その場合は一般経路に回す。

上位16 tritが双方ともゼロの場合、両数の絶対値は `(3^16-1)/2` 以下で、積は常に32 trit範囲に収まる。`trit_mul_low16` は下位16 tritだけを `pext` と小表で復号し、CPU乗算後に再符号化する。全幅の復号を省けるため、小さな通常の数値同士では速い。`trit_mul_hybrid` は疎な定数を先に判定し、それ以外で両数の上位16 tritがゼロならこの経路を使う。大きな一般の数値には全幅の変換方式を残す。

提案された「偶数・奇数ブロックを疎に展開し、二進乗算器で部分積を並列計算する」考え方も試した。[Kronecker substitution](https://flintlib.org/doc/algorithms/polynomials/kronecker.html) の小規模版である。8 tritの `+` と `-` のbit面をそれぞれ4 bit間隔に `pdep` で広げ、`(+)(+)`, `(-)(-)`, `(+)(-)`, `(-)(+)` の4回の二進乗算で畳み込み係数を得る。8桁同士の部分積では1係数は最大8なので、4 bit間隔なら二進carryが隣の係数へ漏れない。最後に16係数を平衡3進へ正規化する。`trit_mul_low8_kronecker` は正しい結果を返すが、この正規化ループが重い。32 trit全体では係数が最大32となり、1係数に少なくとも6 bitの間隔、符号付きの値を直接扱うならさらに注意が必要で、64/128 bit乗算1回に収められない。8 tritブロックを組み合わせる方式も多数の部分積を要する。ハードウェアの乗算器を活用できる可能性はあるが、今回の素朴な分割では速くならなかった。

[Jones の乗除算の解説](https://homepage.cs.uiowa.edu/~jones/ternary/multiply.shtml)も、一般乗算を桁の選択と部分積の累積として説明している。現時点で、一般の32 trit同士の乗算については、入力の大きさに応じて短い復号または全幅復号を選ぶのがよい。

その後、2/4/8/16 tritブロックと `PCLMULQDQ`、正規化を[追試](block-mul.md)した。**全幅乱数の `mod 3^32` 乗算**では、16 tritに分けて交差項を整数のまま合算する方法が全幅復号・128 bit剰余より速い。範囲エラーを要求する仕様への適用は別途検討が必要である。

## 除算: `±1` と割り切れる `±3^k`

`+1` 除算は元の値、`-1` 除算は符号反転。`±3^k` で**割り切れる**なら、下位 `k` trit がすべて0なので、2 bitずつ右シフトして必要なら符号反転する。

端数がある場合、単純な右シフトはC式のゼロ方向丸めとは異なる。`x=3^k q+r`（`r` は下位 `k` trit の平衡値）とすると、`q>0,r<0` なら結果は `q-1`、`q<0,r>0` なら `q+1`。実験関数 `trit_div_pow3` は最高位の非ゼロ tritで `q,r` の符号を得て補正する。正しさは全指数 `k=0..31`、小整数の網羅と全幅乱数で確認した。しかし、端数のある場合はこの補正が重く、変換方式より速いとは言えなかった。`trit_div_hybrid` は `±1` または割り切れる `±3^k` だけを専用経路にし、それ以外は一般経路へ回す。

一般除算で x86 の整数除算を避けるため、復号後の値を倍精度浮動小数点で割り、整数の積と余りで商を補正する方法も試した。32 tritの絶対値は `2^50` 未満で両入力は binary64 で正確に表せる。[浮動小数点除算を利用する整数除算の分析](https://marc-b-reynolds.github.io/math/2026/08/10/IntDivByFP.html)を参考にしたが、このCPUでは変換方式＋整数除算より遅かった。ゼロ除算の本番用エラー処理は未実装。

## 測定と採用判断

Intel i7-1355U、WSL2、GCC 13.3、`-O3 -march=native`、`taskset -c 2`。1024要素を繰り返し処理し、各実行内で3回測定した中央値を、さらにプログラム5回の中央値にした。単位は ns/値。WSL2と周波数の揺れがあるので、同じ行の入力・実行内で比較する。

| 入力・演算 | packed 専用経路 | 変換方式 | 判断 |
| --- | ---: | ---: | --- |
| 一般の減算 | 3.92 | 10.86 | BCT 補正減算を採用候補 |
| `±3^k` 乗算 | 3.50 | 11.64 | シフトを採用候補 |
| 非ゼロ2 tritの乗算 | 7.21 | 11.54 | 定数が既知・安全なら採用候補 |
| 上位16 tritがゼロの2数の乗算 | 7.61 | 11.95 | 半幅復号を採用候補 |
| 8 tritの疎係数畳み込み試作 | 193.36 | 11.37 | この方法の正規化ループは遅い |
| `±1` 除算 | 2.73 | 13.36 | 恒等変換・符号反転を採用候補 |
| 割り切れる `±3^k` 除算 | 2.83 | 13.28 | シフトを採用候補 |
| 端数を含む `±3^k` 除算 | 13.64（hybrid） | 13.50 | 一般経路を維持 |
| 小整数同士の乗算 | 8.91（hybrid） | 11.95 | 疎な値または半幅復号を選ぶ |
| 一般の除算 | 14.55（hybrid） | 13.34 | 変換方式を維持 |
| 一般の除算・浮動小数点経由 | 16.00 | 13.34 | 不採用 |

上の数値は関数呼び出しを含む。2 trit 乗算の `hybrid` 判定を含めると9.68 ns/値。コンパイラが定数の形を把握できるなら、実行時に `popcnt` で毎回判定するより、最初から専用の命令列を生成する方がよい。桁上がりを含む一般乗除算の「packed のままの高速解」や全CPUでの最適性は見つかっていない。

本番では `mod 3^32` による循環と範囲エラーのどちらを言語仕様とするか決める必要がある。一般経路は今は `assert` で範囲を確認し、専用シフトは循環結果を返す。統一したオーバーフロー処理を追加するまでは実験用実装である。
