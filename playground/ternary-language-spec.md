# 平衡3進数言語／コンパイラ仕様案

状態: 構想段階。言語名、記号、文法の細部は仮。

## 設計思想と到達目標

**C++風の波括弧と式、Python風の関数名、できるだけ少ない機能と構造**を採用する。利用者のソースをコンパイルし、平衡3進数ランタイムを呼ぶ x86-64 コードを生成する。インタープリタではなく、コンパイラを主経路とする。最終目標はAtCoderで使える単一ソースを生成し、[3進数Fenwick Treeの記事](https://trap.jp/post/2830/)のTITをこの言語で実装して提出すること。

ランタイムの値表現、演算、呼び出し規約、提出形式は[アセンブリ仕様案](ternary-assembly-spec.md)を参照する。言語の利用者には内部の2 bit符号化を意識させない。

## 最初の言語モデル

- 基本型は **64 bit に詰めた32 trit 固定幅**の平衡3進整数 `trint` ひとつ。ソース中の `123` や `-5` は**10進数で書かれた整数値**であり、コンパイラが内部の trit 表現に変換する。負号は単項演算子。10進数の入出力を標準とする。
- 即値は、コンパイル時に値が確定するなら変換済みの packed trit 定数を生成してよい。実行時に10進数を読み込んだ値はランタイムの変換関数を使う。この2経路が同じ内部表現になることを保証する。
- 変数は宣言と代入で扱う。配列 `trint a[SIZE];` は要素数がコンパイル時に決まる固定長配列。`SIZE` には定数整数式を許す案とし、動的配列・構造体・クラスは初期範囲に含めない。添字は整数値として評価し、実際のアドレス計算は2進数CPU上で行う。
- 最初はトップレベルと `main` 相当の処理だけを持ち、利用者定義関数は後回しにする。変数名の可視性はプログラム全体で共通。`if`、`for`、`while` の波括弧は**スコープを作らない**。反復変数も同じ変数領域に存在する。重複宣言はコンパイルエラーとする案。
- 文より式を中心に構文を設計する。代入・演算・添字参照・組み込み関数呼び出しは式として扱う。`if`、`while`、`for` 自体を値を返す式にするかは未決定。
- 条件は当面 `0` が偽、非0が真。比較と論理演算は `0` または `1` を返す案。`&&` と `||` の短絡評価を想定する。

## 文法の骨格（仮のEBNF）

```ebnf
program   = { declaration | statement } ;
declaration = "trint", identifier, [ "[", constant_expr, "]" ], [ "=", expr ], ";" ;
statement = block | expr, ";" | if_stmt | while_stmt | for_stmt ;
block     = "{", { declaration | statement }, "}" ;
if_stmt   = "if", "(", expr, ")", block, [ "else", block ] ;
while_stmt = "while", "(", expr, ")", block ;
for_stmt  = "for", "(", identifier, "in", "range", "(", [ expr, "," ], expr, [ ",", expr ], ")", ")", block ;
expr      = assignment | binary_expr | unary_expr | call | identifier | literal | array_access | "(", expr, ")" ;
```

これは全演算子の優先順位・結合規則を省いた**骨格**で、完成したBNFではない。まず実装する演算子表を決めてから、詳細な文法に展開する。`for (i in range(n))` は `i = 0, 1, ..., n-1`、`range(a, b)` は `a` 以上 `b` 未満、`range(a, b, step)` は `step` の向きに進み終端を含まない、というPythonに近い意味を候補とする。`step = 0` の扱いは要決定。

## 演算と組み込み関数

通常の算術 `+ - * / %`、比較 `== != < <= > >=`、代入 `=`、論理 `! && ||` を候補とする。trit単位の演算はブログのおまけにならい `&` = 各桁の最小、`|` = 各桁の最大、`^` = 各桁の積、`~` = `+ → - → 0 → +` の巡回を候補とする。`<<` と `>>` は**trit単位**のシフトとし、ビット単位の意味と混同しない。演算子と優先順位は実装前に固定する。

最初の組み込み関数候補は `input()`（標準入力から次の10進整数を読む）、`print(x)`（10進整数と改行を出力）、`digit(x, i)`（下から `i` 番目の trit）、`plus_count(x)`、`zero_count(x)`、`minus_count(x)`。3つの count 関数は32 trit 全体を数え、戻り値は `trint`。先頭の `0` 埋めも数える。入力を行単位にするかトークン単位にするかはAtCoder向けに決める。TITで実際に必要な補助関数は、その用途を確認して追加する。

## 想定するプログラムの形（構文例、未実装）

```text
trint n = input();
trint tree[32768];
trint i = 0;
for (i in range(n)) {
    tree[i] = input();
}
trint answer = 0;
while (n > 0) {
    answer = answer + tree[n];
    n = n - 1;
}
print(answer);
```

これは構文と入出力を示す例で、TITのアルゴリズムそのものではない。TITはユーザー定義関数・構造体なしでも、配列と変数を `main` 相当の処理に置けば記述できる見込み。元記事に合わせて添字を1-indexedにする場合は、宣言した配列の0番を空ける。

## コンパイラと提出形式

字句解析 → 構文解析 → 名前と型・配列サイズの検査 → 中間表現または直接コード生成 → ランタイム結合、という順を想定する。初期版のコンパイラはPython製でもよいが、生成プログラムは単独で実行できるようにする。コンパイラ本体をAtCoderへ送る必要はなく、**コンパイル済みの提出用ソース**を送る方針。

開発時は生成したGASとランタイムGASを別ファイルにできる。提出時は別ツール [`gas_to_cpp.py`](../25B31026/codes/gas_to_cpp.py) に両方を渡し、GASをトップレベル `asm` に同梱した単一の `Main.cpp` を作る。これをAtCoderのGCC C++枠へ提出する。GASの命令や `%` は変換せず、C++の生文字列で包む。AtCoderの[公式言語一覧](https://img.atcoder.jp/file/language-update/2025-10/language-list.html)ではx64アセンブリ枠はNASMなので、GASはその枠に直接提出しない。生成物のサイズ、コンパイル時間、実行時間を含め、簡単な問題で提出実験をする。

## 実装と検証の順序

1. trit表現と10進変換、加減算、比較、シフトを小さなランタイムとして作り、単純な実装を正しさの基準にする。
2. `print(input())`、変数、式、`if`、`while`、`for`、固定長配列までコンパイラを育てる。
3. TITをこの言語で記述し、元記事の実装と同じ入力に対して結果を照合する。
4. GASからC++への変換ツールで単一ソースを生成し、AtCoderのGCC C++枠で提出して動作を確かめる。
5. 計測結果を見ながらアセンブリの trit 演算を高速化する。具体的な手法はここでは規定しない。
