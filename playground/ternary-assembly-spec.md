# 平衡3進数ランタイム／アセンブリ仕様案

状態: 構想段階。符号化と高速化の第一候補は[性能実験](ternary-experiments/README.md)で決めた暫定案であり、言語仕様やABIの未決定事項は残る。

## 目的と境界

x86-64 の2進数CPU上で、平衡3進数の値と桁操作を扱う。ユーザーが書く言語から呼び出せる演算群を GNU assembler (GAS) の x86-64 アセンブリで実装する。これは独立したCPU全体のエミュレータではなく、まずは**平衡3進数の演算ランタイム**とする。仮想命令、独立したレジスタ集合、バイトコードの実行器が必要になったときにVM層を追加する。

アセンブリ中の `__trit_add:` などは関数の入口を表すラベルであり、複数の関数をまとめたものは通常「ライブラリ」または「ランタイムライブラリ」と呼べる。「ヘッダー」は主に宣言を収めるもので、実装を貼り込む形式なら「ランタイムのソースを連結する」と呼ぶ方が正確。

## 値の表現

- 各 trit は `-1`, `0`, `+1` の3値。候補の符号化は `-1 → 01`, `0 → 00`, `+1 → 10`。`11` は無効値として予約する。符号化は実装前に変更可能。
- 右端の trit を最下位桁とする。幅は **32 trit 固定**で、64 bit ワードに2 bitずつ詰める。値は `Σ digit[i] × 3^i` (`0 ≤ i < 32`)。表現範囲は `-(3^32-1)/2` から `+(3^32-1)/2`。符号化は仮だが、幅はこの設計の前提とする。
- 例: `+0-0` は **4 trit** で、上の仮符号化なら `10 00 01 00`、連結して `10000100`。元のメモの「3 trit」は桁数を修正したもの。
- 内部表現はビット列だが、`+` や大小比較は平衡3進数の**数値**として解釈する。`11` を生成しないことを全演算の不変条件とする。
- `trit_shift_left(x, k)` は2 bitずつ左にずらす桁シフト、右シフトは空いた桁を `0` とする。算術上の `3^k` 倍と切り捨ては、幅とオーバーフローの扱いを決めてから定義する。

## ランタイムに求める公開操作

公開名は仮称。コンパイラからは下表の操作を呼び出す。実装の一部をインライン化しても、言語上の意味は同じにする。

| 種類 | 操作例 | 意味 |
| --- | --- | --- |
| 変換 | `__trit_from_i64`, `__trit_to_i64` | 10進整数との相互変換。範囲外の扱いは要決定 |
| 算術 | `__trit_add`, `__trit_sub`, `__trit_mul`, `__trit_div`, `__trit_mod`, `__trit_neg` | 平衡3進数の数値演算。`__trit_neg` は全桁の `+1` と `-1` を交換する。除算の丸めと例外は要決定 |
| 比較 | `__trit_eq`, `__trit_lt` など | 数値比較。返り値の真偽表現はABIで固定する |
| 桁操作 | `__trit_shl`, `__trit_shr`, `__trit_digit` | trit 単位シフト、指定桁取得 |
| 桁数集計 | `__trit_plus_count`, `__trit_zero_count`, `__trit_minus_count` | 32桁全体でそれぞれ `+1`、`0`、`-1` の桁数を数える。結果は `0`～`32` を表す packed `trint` |
| 桁ごとの演算 | `__trit_min`, `__trit_max`, `__trit_product`, `__trit_cycle` | ブログのおまけの `&`, `|`, `^`, `~` に相当する候補 |
| 入出力 | `__trit_read_decimal`, `__trit_print_decimal` | AtCoder の10進数入出力と内部表現の橋渡し |

最初から全操作を実装する必要はない。TITに必要な変換、加減算、比較、シフト、桁取得を優先し、除算・剰余などは必要になった段階で追加する。TIT固有の添字操作も、一般操作で煩雑ならランタイム関数にしてよい。ブログのTITは1-indexedで、値の集計・更新を平衡3進数の桁に沿って進める。対象とする具体的なTITの挙動は[元記事](https://trap.jp/post/2830/)に合わせる。

桁数集計の対象には上位の `0` 埋めも含む。したがって任意の正しい値 `x` について `plus_count(x) + zero_count(x) + minus_count(x) = 32`。ゼロ値なら `zero_count(0) = 32`。必要なら後で「先頭の0を除いた有効桁数」は別操作として定義する。

演算の歴史的な例と、どこまでが共通の考え方かは[3進数演算の調査メモ](ternary-operations-research.md)に記す。

## 暫定実装方針

[実験結果](ternary-experiments/README.md)に基づき、`-1=01, 0=00, +1=10` を第一候補とする。ゼロが全ビット0となり、配列のゼロ初期化と `.bss` をそのまま使える。`__trit_neg`、`min/max/product/cycle`、桁数集計、比較は packed 値のまま処理する。`__trit_neg` は加法逆元であり、最も単純な実装は各2 bit内の交換である。`cycle` の方向は別途明記する必要があり、逆方向は別操作として扱う。

加算の第一候補は[復号しないBCT補正加算](ternary-experiments/bct-adder.md)。現在の符号化を補正計算中だけ `-=00,0=01,+=10` に変え、二進CPUの加算器に32桁のcarryを処理させる。減算は[BCT変換後に第2項を符号反転して同じ加算器へ渡す](ternary-experiments/mul-div-sub.md)。一般の乗除算の第一候補は packed 値を `int64_t` に変換し、CPUの整数演算を行ってから packed 値へ戻す方法。乗算の `±3^k` と非ゼロ2 tritの定数、上位16 tritが両方ゼロの乗算、除算の `±1` と割り切れる `±3^k` には専用経路を設けられる。BMI2 の `pext` を使える CPU では8 tritごとの小表で変換し、利用できない場合には4 tritごとの小表で代替する。32 trit の積の中間結果は `int64_t` を超え得るので、範囲判定には128 bit整数を使う。配列全体への桁演算には AVX2 バッチ関数を選択肢とするが、1ワードずつの関数呼び出しにはスカラ実装を使う。最終的な命令選択と配布先CPUでの性能は再測定する。

## 呼び出し規約とソースの分割

- 開発時は `runtime.s` のような別ファイルに関数を置き、生成されたアセンブリと一緒に `gcc` でリンクする案を第一候補とする。これならランタイムを直接テストでき、生成コードにも同じ関数を使える。
- x86-64 System V ABI を使う。整数／ポインタ引数は順に `%rdi`, `%rsi`, `%rdx`, `%rcx`, `%r8`, `%r9`、返り値は `%rax`。初期案では packed 64-bit 値を1引数／1返り値として渡す。`%rbx`, `%rbp`, `%r12`～`%r15` の保存、関数呼び出し前のスタック整列などもABIに従う。
- シンボルの重複を防ぐため、公開関数だけを `.globl` にし、内部ラベルはローカルにする。将来、値が複数ワードになるならABIも再設計する。
- AtCoderへの提出形式は **C++ソース1ファイル**に固定する。別ツール [`gas_to_cpp.py`](gas_to_cpp.py) がランタイムと生成プログラムのGASソースを受け取り、トップレベルの `asm(R"区切り(... )区切り")` に同梱した `Main.cpp` を返す。GAS自体の構文は変換しない。C++には `main` を重複定義せず、アセンブリ側の `main` をリンカに公開する。
- AtCoderのx64アセンブリ提出枠は **NASM** (`Main.asm`) であり、このGASソースはその枠には送らない。GCCのC++枠での実提出は、単純な問題で別途確認する。

変換ツールの使用例（ランタイムを先に、生成プログラムを後に渡す）:

```sh
python playground/gas_to_cpp.py playground/runtime.s playground/generated.s -o Main.cpp
g++ -std=gnu++23 -O2 Main.cpp -o main
```

この2つの `.s` は今後作るファイル名の例。`-o` を省くと生成したC++を標準出力へ書く。各GASファイルの間には改行を入れるだけで、命令、レジスタ名、`%` は書き換えない。

参考: [AtCoderの言語一覧](https://img.atcoder.jp/file/language-update/2025-10/language-list.html)。
