# 3進数コンピュータの演算についての調査メモ

調査日: 2026-11-17。主な対象は平衡3進数 `{-1, 0, +1}`。ここに挙げる演算は**歴史上の実機・研究上の論理素子・個人製VM**のものを区別して読む。通常の3進数 `0,1,2` を使う例も比較対象として明示する。これらをひとつの標準ISAとして混ぜない。

## 結論

調べた範囲では、3進数コンピュータ全般に通用する**単一の命令セットや演算子記法の標準**は見つからなかった。共通する核は、整数としての加減算・乗算、符号反転、比較や条件分岐、桁シフト、入出力である。一方、tritごとの「AND」「XOR」「NOT」は何を真・偽・中間値とするか、数値と見るか論理値と見るかで定義が変わる。したがって、この言語では演算の名前と真理値表を自分たちで明記する必要がある。これは以下の資料を比較した**設計上の推論**であり、網羅的な標準化調査の結論ではない。

## 歴史上の実機: Setun と Setun 70

開発者 Brusentsov らによる[論文（英語）](https://icfcst.it-museum.com/Symposium/Proceedings/Brusentsov.pdf)と[モスクワ大学公開の原著（ロシア語、命令表を含む）](https://ternarycomp.cs.msu.ru/Papers/Petroz.pdf)によると、Setunは1958年末に稼働した平衡3進数の実機で、18 trit の演算レジスタと9 trit の命令を持つ。24命令の中にシフト、正規化、乗算と加算の組み合わせ、符号に基づく条件分岐がある。原著は桁ごとの乗算にも触れている。Setun 70は6 trit の tryte と2つのスタックを使い、短い操作・アドレス列を実行する。両機の幅や命令体系はこの計画の32 trit ワードとは異なるため、参考例として扱う。

参考になる点は、平衡3進数では符号反転が各 trit の `+` と `-` の交換になること、結果の符号が3値 `-, 0, +` になること、桁シフトや桁ごとの演算が自然な操作として現れること。一方、3種類の trit 数を数える命令がSetunの標準命令だったとは、この資料からは確認できない。

## 3値論理の研究: 基本演算も一意ではない

Douglas W. Jones の[3値論理の解説](https://homepage.cs.uiowa.edu/~dwjones/ternary/logic.shtml)では、`- < 0 < +` と置いたときの `min` / `max`、符号反転 `- ↔ +`、巡回 `- → 0 → + → -` とその逆、各種の3値排他的論理和、桁ごとの mod 3 加算、consensus（2つが同じ非ゼロならその値、それ以外は0）などが区別されている。特に「3値 XOR」には複数の自然な候補がある。同資料は `min/max/符号反転` だけでは全3値関数を表現できないことも説明している。

この計画の `__trit_product` は各桁の**数値の積**、`__trit_cycle` は桁の巡回、`__trit_neg` は符号反転と呼び分けるのが安全。言語の `^` や `~` へ割り当てる場合も、C++のビット演算や2値論理と同じ意味だと推測させない説明が要る。`__trit_consensus` や3値比較結果 `-,0,+` は面白い追加候補だが、TITに必要かを先に確認する。

## 個人製のVMとの比較

[ternary-vm](https://github.com/kostyk348/ternary-vm) は9 trit の値を持つ個人製VMで、`LOAD/STORE/ADD/SUB/MUL/NEG/MOV/JMP/JZ/JNZ/OUT` などを公開している。算術のあふれは**飽和**させる。この一点だけでも、本計画で未決定のあふれ処理を暗黙に決めてはいけないことが分かる。

[Tera](https://github.com/jorbDehmel/tera) も9 trit の仮想CPUだが、こちらの各 trit は **`0,1,2`** であり、平衡3進数ではない。`incr/decr`、条件用の制御バッファ、比較を組み合わせる方式を採る。数の表現や命令の選び方が実装ごとに異なる例として挙げる。

## この計画への反映

| 区分 | この計画での扱い |
| --- | --- |
| 核となる数値演算 | 加減乗除、符号反転、比較、桁シフトを明示的に定義する |
| 桁ごとの演算 | `min/max/product/cycle` を候補とし、各 trit の真理値表を固定する |
| 数え上げ | `__trit_plus_count`、`__trit_zero_count`、`__trit_minus_count` を**本計画の便利な公開関数**として追加する。歴史的な標準命令とは主張しない |
| 将来候補 | 桁ごとの mod 3 加算、consensus、3値の符号比較、先頭の有効桁数。TITや競プロの実例から必要性を判断する |

この計画では count の対象を固定幅の**32 trit 全体**とする。`zero_count` は先頭のゼロ埋めを含むため、3つの count の和は常に32。`plus_count` と `minus_count` の差は「各桁値の単純な和」ではあるが、平衡3進数の数値そのものではない。用途を混同しない。

## `min/max/cycle/product` は完全か

**1 trit ごとの有限3値論理としては完全。実は `product` を除いた `min/max/cycle` だけで完全**である。ここでいう完全とは、任意の有限個の trit を入力し、1 trit を返す任意の真理値表を、これらの演算の合成で表せること。`cycle` は `- → 0 → + → -` とする。Postの多値論理には `max` と巡回演算だけで全関数を表せる結果もある（[Postの研究を解説する論文](https://richardzach.org/wp-content/uploads/2009/09/history.pdf)）。以下はこの計画の演算定義に即した独立の構成。

1. 任意の入力 trit `x` から、`k_minus = min(x, cycle(x), cycle(cycle(x)))` は常に `-`。`k_zero = cycle(k_minus)`、`k_plus = cycle(k_zero)` で定数 `0` と `+` も作れる。
2. `neg(x) = max(min(x, cycle(x)), cycle(max(x, cycle(x))))` は `- ↔ +`、`0 → 0`。これは3入力値を代入して確かめられる。
3. `is_plus(x) = max(x, 0)`、`is_minus(x) = max(neg(x), 0)`、`is_zero(x) = max(cycle(x), 0)` は、該当するときだけ `+`、それ以外は `0` を返す。複数入力の特定の組み合わせに対する判定は、対応する `is_*` を `min` で結合する。
4. その判定を `I` とすると、`cycle(I)` はその組み合わせで `-`、それ以外で `+`。`neg(cycle(cycle(I)))` はその組み合わせで `0`、それ以外で `+`。任意の真理値表について、出力が `-` または `0` の行の式をすべて `min` で結合すれば、残りの行は `+` となり、その関数を実現できる。

実際に全27種類の単項関数が生成されることと、全 `3^9 = 19,683` 種類の2入力真理値表で上の構成が一致することをPythonで照合した。これは**表現可能性**の証明であり、生成した式が短い・速いという主張ではない。`product` は1桁の積を簡潔に書くために引き続き価値がある。

ただし64 bit ワードへ4演算を trit ごとに適用するだけなら、出力の第 `i` 桁は入力の**第 `i` 桁だけ**に依存する。ゆえに別の桁を参照する trit shift、桁上がりを伴う整数加算、32桁を集計する `plus_count/zero_count/minus_count` は作れない。ランタイム全体や競プロ向け言語としては、これらの桁間操作とメモリ・制御フローを別に備える必要がある。
